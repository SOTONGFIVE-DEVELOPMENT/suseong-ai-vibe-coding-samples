# 첫날 워크북 — 업무 설명을 검증 가능한 요청으로 바꾸기

이 워크북에는 실제 민원, 직원, 내부 자료를 넣지 마세요. 공개 자료와 가상 자료로 수업을 진행합니다. 독립 수행·도움 받음·미완료를 구분하고 AI의 답변이 아니라 관찰한 결과로 판단합니다.

1. [활동 1: 업무 요구사항](day1/01-requirements.md) — 사용자, 입력, 처리, 출력, 예외, 성공 기준을 적습니다.
2. [활동 2: AI 답변 검증](day1/02-verification.md) — 맞는 예, 0건, 빈 값, 실패 상황을 비교합니다.
3. [활동 3: 자기 업무로 응용](day1/03-transfer.md) — 자료 이름과 조건 하나를 바꾸고 다른 사람이 재현하게 합니다.

[JSON·API 자료카드](day1/04-data-card.md)는 JSON 설명과 공개 데이터 검토 때 사용합니다. key/value 하나를 읽고 자료 범위·원본 수집·이번 재생·직접 호출 여부를 구분해 적습니다.

첫날 활동지의 완료 기준은 자기 업무의 공개 목록이나 가상 목록을 다루는 요청문을 작성하고, 최소 3개 검증 입력의 기대값을 먼저 적은 뒤 관찰값과 비교해 통과/미완료를 판단하는 것입니다. 도움을 받은 항목은 혼자 다시 한 번 실행하면 독립 수행으로 바꿀 수 있습니다.

전체 과정의 최종 완료 기준은 00에서 시작한 도서관 앱을 06까지 이어 만들어 내 PC에서 실행하는 것입니다. 이름·지역·유형 AND 검색, 0건·초기화, URL 새로고침·뒤로/앞으로 복원, 전화 링크, API 저장·실패 보존·재시작, 완성 예시의 화면 구성을 모두 확인합니다. 외부 배포는 필요하지 않으며 업무 목록 응용은 최종 앱 완성 뒤 선택 활동입니다.
