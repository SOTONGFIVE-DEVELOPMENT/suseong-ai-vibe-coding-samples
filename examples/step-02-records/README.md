# STEP 02 — JSON 파일과 목록

이 폴더는 해당 단계의 비교·복구용 정상본이며 다른 단계나 상위 폴더 없이 독립 실행할 수 있습니다. 자료는 2026-10-04에 실제 공공 API 응답에서 선정한 도서관 3곳의 저장 예제입니다. 기본 sample 실행은 이 파일을 재생하므로 키가 필요 없고 외부 API에 접속하지 않습니다. 기관 원본 이름·주소·전화·기준일을 보존합니다.

## 실행

Node.js **22.x**와 npm이 필요합니다. macOS의 터미널 또는 Windows의 PowerShell에서 **이 파일과 package.json이 있는 폴더**를 엽니다.

```sh
node --version
npm --version
npm ci
npm run dev
```

브라우저에서 [실습 화면](http://127.0.0.1:3000)을 엽니다. 서버가 3000번 포트를 다른 프로그램이 사용 중이라고 안내하면 `Ctrl+C`로 중지한 뒤 `npm run dev -- --port 3001`로 실행하고 `http://127.0.0.1:3001`을 여세요. 실습 서버를 중지하려면 터미널에서 **Ctrl+C**를 누릅니다. 코드를 변경하면 개발 서버가 화면을 다시 만듭니다. JSON 파일을 변경했을 때는 브라우저를 새로고침합니다.

Windows에서 `npm.ps1` 실행 정책 오류가 나면 같은 명령에서 `npm`을 `npm.cmd`로 바꾸세요. 전역 실행 정책은 바꿀 필요가 없습니다. Node.js를 설치한 뒤에는 터미널을 새로 여세요.

## 진행 순서

1. 00 시작본을 본인의 작업 폴더에 한 번 풀고, 그 프로젝트를 01 → 02 → 03 → 04 → 05까지 계속 고칩니다. 단계마다 새 ZIP으로 작업을 바꾸지 않습니다.
2. [PROMPTS.md](PROMPTS.md)의 해당 단계 요청을 같은 작업 폴더에서 수행합니다. 이 정상본을 직접 열었다면 이미 구현된 부분을 먼저 읽고 비교합니다.
3. 아래 성공 기준과 같은 입력을 실행하고, 변경 파일과 재현 결과를 확인합니다. 단계 ZIP은 막혔을 때 비교하거나 새 복구 폴더에서 재개하는 자료입니다.
4. [CHECKLIST.md](CHECKLIST.md)에 실행 폴더, 자료 종류, 입력, 기대값, 관찰값과 도움 여부를 기록합니다. 직접 기관 API 호출 여부도 따로 적습니다.

## 성공 기준

- [ ] 실제 저장 예제 총 3건
- [ ] 수성구 2건·중구 1건
- [ ] 실습 복사본에서 용학 이름 변경 후 새로고침 반영·원본 복구

화면에 보이는 결과와 파일/API 결과가 일치해야 완료입니다. AI가 완료했다고 답한 것만으로는 완료로 표시하지 마세요.

## 중단·재개 지점

아래 성공 기준을 통과한 뒤 다음 단계인 **이름 검색(03)**로 갑니다. 시간이 끝나면 실행 폴더 전체 경로, 마지막 통과 기준, 미완료 입력·오류, 다음 요청을 CHECKLIST에 남기고 서버를 Ctrl+C로 중지합니다. 다음 시간에는 같은 폴더에서 `npm run dev`로 이어갑니다. 2일차 시간 안에 마지막 단계까지 끝내지 못해도 중간 단계를 완료로 표시하지 않습니다. 개인 업무 전이는 최종 앱을 완성한 뒤 별도 가상 복사본에서 선택합니다.

## 파일 찾기

`app/page.js`는 화면의 시작 파일이고, `stage.json`에는 단계 이름과 성공 기준이 들어 있습니다. `data/records.json`은 교육용 JSON 자료이며 00과 01 단계에서는 아직 화면에 연결하지 않습니다. 02 단계부터는 `app/api/libraries/route.js`에서 파일을 읽고 `app/library-browser.js`가 응답을 화면에 표시합니다.

실제 주소를 빈 값으로 바꾸지 마세요. 누락 값 처리는 `lib/filter.mjs`의 `displayValue` 단위 테스트로 확인합니다. 화면에서 빈 값을 시험하거나 자기 업무로 바꾸려면 아래 가상 전이 복사본을 사용하세요. 실제 수집본과 복구 seed는 보존합니다.

## 가상 자료로 자기 업무 연습하기

이 활동은 최종 로컬 앱을 완성한 뒤 선택합니다. 현재 단계의 필수 제작·성공 기준과 별도로 기록합니다.

단계 ZIP을 **별도 폴더**에 새로 풀고 `npm ci`를 마칩니다. 교육장에서는 이 설치를 전이 활동 전에 준비하세요. 그 복사본의 서버를 Ctrl+C로 중지하고 실행합니다.

```sh
npm run prepare-transfer -- --copy
npm run dev
```

`--copy`는 별도 실습 복사본을 준비했다는 표시입니다. 없으면 명령은 파일을 바꾸지 않습니다. `data/records.synthetic.json`의 가상 시설 A·B·C를 `data/records.json`으로 복사하고 이전 파일을 백업합니다. 다시 실행하면 현재 변경도 새 백업으로 보존한 뒤 가상 시작 자료로 돌아갑니다. `records.seed.json`과 실제 저장 응답은 수정하지 않습니다.

화면 제목은 **가상 업무 목록 조회**, 자료 배지는 **가상 연습 자료 · 외부 호출 없음**으로 바뀝니다. 기관 수집 시각·원본 전체 건수·응답 지문은 표시하지 않습니다. `dataMode=sample`은 로컬 자료를 읽는 방식이고 `dataKind=synthetic`은 자료가 가상임을 뜻합니다. `meta`는 그대로 두고 `items`의 이름·지역·유형을 자기 업무의 가상 값으로 바꾸세요. 빈 주소·기준일은 ‘정보 없음’으로 보입니다. 항목을 늘리거나 줄이면 `meta.totalCount`도 목록 길이에 맞춥니다.

가상 시작 자료에서는 이름 `시설 B`가 1건, `가상 동부`가 2건, `가상 동부 + 문화시설`이 1건입니다. 바꿀 조건 하나를 고르고 정상·0건·빈 값 또는 실패의 기대값을 먼저 적은 뒤 같은 입력으로 비교하세요. 선택하지 않은 기능은 평가하지 않습니다. 실제 도서관의 사월 검색 기준은 이 활동에 적용하지 않습니다.

가상 전이 중에는 API 가져오기 영역을 표시하지 않습니다. 실제 정상본으로 돌아가려면 서버를 중지하고 `npm run reset-data`를 실행한 뒤 다시 시작합니다. 전이와 복구 모두 이전 파일을 백업하며 기관 API에는 접속하지 않습니다.

`npm test`는 보존한 실제·가상 fixture의 회귀검사입니다. 자기 업무로 바꾼 현재 파일의 성취는 [CHECKLIST.md](CHECKLIST.md)의 선택 시험으로 직접 확인하세요.

## 검증과 복구

```sh
npm test
npm run build
```

`npm run check`는 두 검증을 순서대로 실행합니다. 개발 서버를 중지한 상태에서 빌드하세요. 빌드한 정상본을 실행하려면 `npm run start`를 사용합니다.

서버를 Ctrl+C로 중지하고 `npm run reset-data`를 실행하면 수정 전 파일을 `data/records.backup.<시각>.json`으로 백업한 뒤 기록된 실제 저장 예제 3건을 복구합니다. 그다음 `npm run dev`로 서버를 다시 시작하세요.

`npm ci`가 실패하면 교육장 네트워크에서 npm registry에 접속되는지 확인하세요. 성공하기 전에는 다음 단계를 눌러 해결됐다고 표시하지 마세요. 설치나 실행이 계속 실패하면 이 ZIP과 오류 문구 중 비밀값이 없는 부분을 보조강사에게 보여 주세요.

## 실습 범위

이 서버는 본인 PC의 127.0.0.1에서만 실행합니다. 공개 서비스로 운영하려면 인증, 쓰기 권한, 운영 저장소 등을 따로 설계해야 합니다. 기관 기준일은 원본값이며 3건은 교육용으로 선정한 일부입니다. 현재 운영 정보는 기관에 별도로 확인합니다.
