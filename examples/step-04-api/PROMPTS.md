# P5 — 같은 앱에 API 가져오기와 저장 통합

출발 상태: 00부터 이어 만든 이름 검색 작업본(03)을 그대로 엽니다. 04 ZIP은 구현 비교·복구 자료이며, 이 ZIP의 독립 실행만으로 제작 완료를 표시하지 않습니다. 기본 sample 재생은 키 없이 전체 기능을 완성하는 필수 경로입니다. 본인 키의 실전 호출은 선택 활동입니다.

## P5 — 내 검색 앱에 통합하기

04 정상본의 `docs/api-spec.md`, `api-response.sample.json`, `data/sample-api-response.json`을 현재 작업본과 함께 Codex가 읽을 수 있게 준비합니다. API 명세와 저장 fixture를 작업본에 복사해도 원본 파일·수집 근거는 수정하지 않습니다.

```text
현재 이름 검색 작업본에 API 가져오기 → 응답 검증 → JSON 파일 저장 → 화면 갱신 기능을 통합해줘. 04 정상본의 API 명세와 실제 저장 응답 3건을 참고하고 기본 sample 모드는 이 저장 응답만 읽어야 해. 외부 API에 접속하지 마. POST /api/import와 저장 응답 재생 버튼을 추가하고, 필수 필드와 건수를 검증한 뒤 data/records.json을 원자적으로 교체해줘. 실패하면 기존 파일과 화면을 유지해. 서버 종료·재시작 후에도 저장 결과가 남아야 해. 시간 초과·응답 형식·인증 오류는 sample의 가상 오류 연습으로 구분해. 기존 이름 검색·0건 안내·초기화와 3→사월 1→없는도서관 0→초기화 3 검증을 그대로 유지해. 기관 원본 이름·주소·전화·기준일, 원본 수집 시각, 원본 전체 242건 중 선정한 3건이라는 범위와 지문을 보존해. 이번 PC 재생·저장 시각은 원본 수집 시각과 구분해. sample은 현재 사용자의 직접 API 호출 성공이라고 쓰지 마. 선택 live 설정은 서버 .env.local에서만 읽고 인증키를 화면·로그·대화·NEXT_PUBLIC_ 변수에 넣지 마. 키를 읽거나 실전 호출은 하지 말고 테스트와 빌드로 확인해. 변경 파일과 같은 입력으로 재시험할 순서를 알려줘.
```

샘플의 `lib/api-source.mjs`, `lib/local-request.mjs`, `lib/store.mjs`는 구현 비교용입니다. 코드 전체를 새 앱으로 바꾸지 말고 현재 검색 작업본에 필요한 변경을 합칩니다. 04 성공 기준을 통과한 뒤 같은 작업본에서 05 복합 조건으로 이어갑니다.

## 결과 검증 요청

```text
현재 구현을 읽고 이미 된 항목과 추가할 항목을 구분해줘. README와 CHECKLIST의 해당 활동 기준마다 실행 폴더, 자료 종류, 입력, 기대 결과, 실제 결과를 비교해줘. 파일을 바꿨다면 변경 파일을 알려주고 npm test와 npm run build를 실행해줘. 실행하지 못한 항목은 미확인으로 써줘. 테스트 통과와 내 화면에서 직접 확인한 수행 상태는 구분해줘. sample 재생 중에는 외부 API에 접속하지 마.
```

## P7 — 실제로 관찰한 문제 한 곳 수정

```text
내 실행 폴더는 [폴더]이고 자료 종류는 [수집본 재생/가상/본인 직접 호출]이야. 입력과 실행 순서는 [입력·순서], 기대 결과는 [기대값], 실제 결과는 [관찰값]이야. 비밀값 없는 오류 문구는 [문구]야. 이 차이를 만드는 문제 한 곳을 확인하고 수정해줘. 기존 정상 자료와 다른 기능을 유지하고 같은 입력으로 재시험해줘. 실행하지 못한 검증은 미확인으로 기록해줘.
```

실제 개인정보, 기관 내부 자료, 인증키를 요청문에 넣지 마세요. 실제 문제를 만나지 않았다면 P7은 미실시로 남깁니다. 일부러 정상 자료를 망가뜨릴 필요는 없습니다.
