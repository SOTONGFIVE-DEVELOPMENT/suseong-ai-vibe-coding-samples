# P5 API 정상본 실행·검증 — Codex 요청문

출발 상태: 03 검색 작업은 보존하고 04 ZIP을 별도 폴더에 풀어 엽니다. 04는 이미 구현된 API 정상본이며 03에 API를 처음부터 만드는 과제가 아닙니다. 기본 sample 재생으로 확인합니다.

## P5 — 별도 API 정상본을 실행하고 비교하기

```text
이 04 API 정상본의 README, 저장 응답 파일, API 가져오기와 저장 코드를 읽어줘. 새 기능을 만들지 말고 sample 재생의 입력 → 검증 → 파일 저장 → 화면 흐름을 설명해줘. 저장 응답 재생, 서버 재시작 후 유지, 오류 연습 후 기존 파일 보존을 확인할 순서를 알려줘. 원본 수집 시각과 이번 PC의 재생·저장 시각을 구분하고 실제 수집본 242건 중 선정한 3건임을 설명해줘. sample은 현재 사용자의 직접 API 호출 성공이 아니야. 인증키를 읽거나 외부 API에 접속하지 말고 npm test와 npm run build로 확인해줘.
```

## 결과 검증 요청

```text
현재 구현을 읽고 이미 된 항목과 추가할 항목을 구분해줘. README와 CHECKLIST의 해당 활동 기준마다 실행 폴더, 자료 종류, 입력, 기대 결과, 실제 결과를 비교해줘. 파일을 바꿨다면 변경 파일을 알려주고 npm test와 npm run build를 실행해줘. 실행하지 못한 항목은 미확인으로 써줘. 선택하지 않은 추가 기능은 평가하지 마. 테스트 통과와 내 화면에서 직접 확인한 수행 상태는 구분해줘.
```

## P7 — 실제로 관찰한 문제 한 곳 수정

```text
내 실행 폴더는 [폴더]이고 자료 종류는 [수집본 재생/가상/본인 직접 호출]이야. 입력과 실행 순서는 [입력·순서], 기대 결과는 [기대값], 실제 결과는 [관찰값]이야. 비밀값 없는 오류 문구는 [문구]야. 이 차이를 만드는 문제 한 곳을 확인하고 수정해줘. 기존 정상 자료와 다른 기능을 유지하고 같은 입력으로 재시험해줘. 실행하지 못한 검증은 미확인으로 기록해줘.
```

실제 개인정보, 기관 내부 자료, 인증키를 요청문에 넣지 마세요. 실제 문제를 만나지 않았다면 P7은 미실시로 남깁니다. 일부러 정상 자료를 망가뜨릴 필요는 없습니다.
