# STEP 04 — API 연결과 저장

이 폴더는 다른 단계나 상위 폴더 없이 독립 실행할 수 있는 정상본입니다. 자료는 2026-10-04에 실제 공공 API 응답에서 선정한 도서관 3곳의 저장 예제입니다. 기본 sample 실행은 이 파일을 재생하므로 키가 필요 없고 외부 API에 접속하지 않습니다. 기관 원본 이름·주소·전화·기준일을 보존합니다.

## 실행

Node.js **22.x**와 npm이 필요합니다. macOS의 터미널 또는 Windows의 PowerShell에서 **이 파일과 package.json이 있는 폴더**를 엽니다.

```sh
node --version
npm --version
npm ci
npm run dev
```

브라우저에서 [실습 화면](http://127.0.0.1:3000)을 엽니다. 서버가 3000번 포트를 다른 프로그램이 사용 중이라고 안내하면 `Ctrl+C`로 중지한 뒤 `npm run dev -- --port 3001`로 실행하고 `http://127.0.0.1:3001`을 여세요. 실습 서버를 중지하려면 터미널에서 **Ctrl+C**를 누릅니다. 코드를 변경하면 개발 서버가 화면을 다시 만듭니다. JSON 파일을 변경했을 때는 브라우저를 새로고침합니다.

Windows에서 `npm.ps1` 실행 정책 오류가 나면 같은 명령에서 `npm`을 `npm.cmd`로 바꾸세요. 전역 실행 정책은 바꿀 필요가 없습니다. Node.js를 설치한 뒤에는 터미널을 새로 여세요.

## 진행 순서

1. 화면을 실행하고 아래 성공 기준을 직접 확인합니다.
2. [PROMPTS.md](PROMPTS.md)의 요청문을 Codex에 입력합니다. 이미 완성된 정상본이므로 기능을 익힐 때는 이전 단계의 복사본에서 시작해 이 폴더와 비교해도 됩니다.
3. Codex가 변경한 파일과 설명을 살펴보고 다시 실행해 같은 결과가 재현되는지 확인합니다.
4. [CHECKLIST.md](CHECKLIST.md)에 결과와 도움 여부를 기록합니다.

## 성공 기준

- [ ] 저장 응답 재생 → 3건 저장
- [ ] 저장 예제 재생과 실제 API 호출을 화면에서 구분
- [ ] 서버 종료·재시작 후 저장 결과 유지
- [ ] 오류 연습 후 기존 파일 유지

화면에 보이는 결과와 파일/API 결과가 일치해야 완료입니다. AI가 완료했다고 답한 것만으로는 완료로 표시하지 마세요.

## 파일 찾기

`app/page.js`는 화면의 시작 파일이고, `stage.json`에는 단계 이름과 성공 기준이 들어 있습니다. `data/records.json`은 교육용 JSON 자료이며 00과 01 단계에서는 아직 화면에 연결하지 않습니다. 02 단계부터는 `app/api/libraries/route.js`에서 파일을 읽고 `app/library-browser.js`가 응답을 화면에 표시합니다.

실제 주소를 빈 값으로 바꾸지 마세요. 누락 값 처리는 `lib/filter.mjs`의 `displayValue` 단위 테스트로 확인합니다. 화면 실험이 필요하면 단계 폴더를 별도로 복사하고 제목에 **임시 빈 값 연습**이라고 표시한 뒤 복사본에서만 주소를 비워 보세요. 원본 정상본은 그대로 보관하며 연습 후 `npm run reset-data`로 복구합니다.

## 검증과 복구

```sh
npm test
npm run build
```

`npm run check`는 두 검증을 순서대로 실행합니다. 개발 서버를 중지한 상태에서 빌드하세요. 빌드한 정상본을 실행하려면 `npm run start`를 사용합니다.

서버를 Ctrl+C로 중지하고 `npm run reset-data`를 실행하면 수정 전 파일을 `data/records.backup.<시각>.json`으로 백업한 뒤 기록된 실제 저장 예제 3건을 복구합니다. 그다음 `npm run dev`로 서버를 다시 시작하세요.

`npm ci`가 실패하면 교육장 네트워크에서 npm registry에 접속되는지 확인하세요. 성공하기 전에는 다음 단계를 눌러 해결됐다고 표시하지 마세요. 설치나 실행이 계속 실패하면 이 ZIP과 오류 문구 중 비밀값이 없는 부분을 보조강사에게 보여 주세요.

## API 선택 활동

[API 명세](docs/api-spec.md)와 [실제 저장 응답 구조](api-response.sample.json)를 먼저 읽습니다. 실행할 때 읽는 파일은 `data/sample-api-response.json`입니다.

기본값은 sample입니다. **저장 응답 재생**은 `data/sample-api-response.json`에 보관한 실제 응답 중 3건을 읽고 검증하며 공공데이터포털에는 접속하지 않습니다. 키나 가입 없이도 전체 수업을 진행할 수 있습니다. 원본 수집 시각(recordedAt)은 2026-10-04 19:17:37 한국 시간으로 유지되고 이 PC 재생·저장 시각(syncedAt)만 갱신됩니다. 원본 응답 242건과 교육용 선정 3건을 구분하세요.

키가 승인된 경우에만 `.env.example`을 `.env.local`로 복사해 `DATA_MODE=live`와 `DATA_GO_KR_SERVICE_KEY`를 본인 편집기에서 설정하고 서버를 재시작합니다. 키를 Codex 대화, 스크린샷, GitHub에 넣지 마세요. `NEXT_PUBLIC_` 키를 만들지 마세요. 실전 호출은 선택 활동입니다. 저장 예제는 강사가 인증해 수집한 실제 자료지만 학생의 sample 재생 성공은 본인 키의 승인·실전 호출 성공을 뜻하지 않습니다. 이 프로젝트의 live 어댑터는 인증키 없이 모의 응답으로 검사했습니다.

실전 호출에 성공하면 선정한 저장 예제 3건 대신 대구광역시 실제 응답의 전체 페이지를 저장합니다. 선정한 저장 예제의 `3→1→0→3` 기준은 실전 자료에는 적용하지 않습니다. 실전 자료를 교육용 저장 예제로 되돌리려면 서버를 중지한 뒤 `.env.local`에서 `DATA_MODE=sample`로 바꾸세요. 이어서 `npm run reset-data`를 실행한 뒤 서버를 다시 시작하세요.

오류 연습에서 시간 초과, 응답 형식 오류, 인증 오류 중 하나를 선택하고 **선택 오류 재현**을 누르세요. 오류 문구를 보고 기존 3건과 저장 파일이 유지되는지 확인합니다. 이 버튼을 눌러 나오는 오류는 교육용으로 재현한 것입니다.

## 실습 범위

이 서버는 본인 PC의 127.0.0.1에서만 실행합니다. 공개 서비스로 운영하려면 인증, 쓰기 권한, 운영 저장소 등을 따로 설계해야 합니다. 기관 기준일은 원본값이며 3건은 교육용으로 선정한 일부입니다. 현재 운영 정보는 기관에 별도로 확인합니다.
