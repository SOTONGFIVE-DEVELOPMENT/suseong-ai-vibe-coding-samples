# 복합 조건·주소 복원·전화 링크 — Codex 요청문

출발 상태: API 가져오기와 이름 검색을 통합한 같은 04 학습 작업본에서 이어갑니다. 05 ZIP은 기능 비교·복구 기준입니다. 이름·지역·유형, 주소 복원, 전화 링크는 최종 앱을 위한 필수 기능입니다. 개인 업무로 바꾸는 활동은 마지막 앱을 완성한 뒤 별도 가상 복사본에서 선택합니다.

## 내 앱의 최종 기능 합치기

```text
현재 API 가져오기와 이름 검색 작업본에 지역과 유형 선택을 모두 추가해줘. 이름 부분 일치·선택 지역·선택 유형을 AND로 결합하고, 결과 건수/전체 건수·0건 안내·전체 초기화를 유지해. 선택 목록은 검색 결과가 아니라 전체 저장 자료에서 만들어서 0건 주소를 직접 열어도 사라지지 않아야 해. 실제 저장 예제에서 처음 3건, 사월 1건, 없는도서관 0건, 대구 수성구 2건, 대구 수성구+작은도서관 1건, 사월+대구 수성구+작은도서관 1건, 사월+대구 중구+작은도서관 0건, 초기화 3건을 검증해. 적용한 이름·지역·유형을 주소의 q·region·type으로 기록하고 새로고침·뒤로 가기·앞으로 가기에서 입력과 결과를 함께 복원해. 입력 중인 글자와 실제 검색을 구분하고 검색 제출 때만 주소를 바꿔. 원본 전화번호를 표에 추가해 tel: 링크로 표시하고 주소·기관 기준일·수집 근거를 보존해. 빈 전화·주소·기준일은 정보 없음으로 표시해. API 저장 응답 재생, 서버 재시작 후 유지, 가상 오류 후 기존 파일 유지 기능은 그대로 동작해야 해. 외부 API나 인증키를 읽지 말고 같은 입력의 회귀 테스트와 빌드로 확인해. 변경 파일과 브라우저에서 재시험할 순서를 알려줘.
```

이 단계 성공 후 같은 로컬 앱에 최종 화면을 적용하고 전체 기능을 다시 확인합니다. 최종 산출물의 공개 배포는 수료 조건이 아닙니다. 2일차 시간이 끝나면 CHECKLIST의 중단·재개 기록을 남기고 같은 폴더에서 이어갑니다.

## 자기 업무로 옮기기 (최종 완성 뒤 선택 활동)

README의 순서대로 별도 가상 전이 복사본에서 `npm run prepare-transfer -- --copy`를 실행한 뒤 요청합니다.

```text
현재 자료는 별도 복사본의 가상 업무 목록이야. dataKind=synthetic과 가상 출처 표시를 유지하고 실제 기관의 출처·수집 시각·원본 건수·응답 지문을 붙이지 마. items의 이름·지역·유형을 [가상 업무 목록]에 맞게 바꾸고, [바꿀 조건 하나]만 수정해줘. 먼저 정상·0건·빈 값 또는 실패 입력의 기대값을 알려줘. 다른 기능은 유지하고 같은 입력으로 관찰 결과를 비교할 순서를 알려줘. API 가져오기 버튼은 실행하지 마.
```

## 결과 검증 요청

```text
현재 구현을 읽고 이미 된 항목과 추가할 항목을 구분해줘. README와 CHECKLIST의 해당 활동 기준마다 실행 폴더, 자료 종류, 입력, 기대 결과, 실제 결과를 비교해줘. 파일을 바꿨다면 변경 파일을 알려주고 npm test와 npm run build를 실행해줘. 실행하지 못한 항목은 미확인으로 써줘. 테스트 통과와 내 화면에서 직접 확인한 수행 상태는 구분해줘. sample 재생 중에는 외부 API에 접속하지 마.
```

## P7 — 실제로 관찰한 문제 한 곳 수정

```text
내 실행 폴더는 [폴더]이고 자료 종류는 [수집본 재생/가상/본인 직접 호출]이야. 입력과 실행 순서는 [입력·순서], 기대 결과는 [기대값], 실제 결과는 [관찰값]이야. 비밀값 없는 오류 문구는 [문구]야. 이 차이를 만드는 문제 한 곳을 확인하고 수정해줘. 기존 정상 자료와 다른 기능을 유지하고 같은 입력으로 재시험해줘. 실행하지 못한 검증은 미확인으로 기록해줘.
```

실제 개인정보, 기관 내부 자료, 인증키를 요청문에 넣지 마세요. 실제 문제를 만나지 않았다면 P7은 미실시로 남깁니다. 일부러 정상 자료를 망가뜨릴 필요는 없습니다.
